# 나의 [감정]들 — 감정을 단정하지 않는 인터랙티브 웹아트

> 출처: `컴퓨터공학부 2021100984 박준현_자기주도학습_설계안.docx`, 생각기록노트 2편(연극 〈701호〉, 《린 허쉬만 리슨: 나의 [나]들》), 지도교수 피드백 3개 항목.
> 가제는 전시 제목의 대괄호 표현을 빌렸다. 최종 제목은 TBD.

## Problem
사람은 지금 느끼는 감정을 한 단어로 말하기 어렵다. 〈701호〉의 진석처럼 짜증처럼 보이는 말 안에 두려움과 조급함이 함께 있을 수 있다. 그런데 기존 감정 인식 기능(표정 분류, 감정 분석)은 입력을 '화남' 같은 단일 라벨로 단정한다. 그러면 사용자는 자기 감정을 들여다볼 기회를 잃고, 틀린 라벨을 받으면 오히려 이해받지 못했다고 느낀다.

이 결과물은 사용자가 입력(웹캠 표정·질문 응답·마우스 움직임)으로 만든 추상 이미지를 보며 **자기 감정에 직접 이름을 붙이고 고칠 수 있게** 한다. 해결하지 않으면 "감정을 다루는 기술은 판정한다"는 기본 설계가 그대로 남는다.

## Background — 감정 연구 동향 (피드백 1 반영)
결과물 설계의 근거가 되는 흐름만 추렸다. 각 항목은 학습성과 보고서에서 출처와 함께 확장한다.

| 관점 | 핵심 주장 | 이 결과물에 주는 시사점 |
|---|---|---|
| 기본 감정 이론 (Ekman) | 기쁨·슬픔·분노·공포·혐오·놀람 등 보편적 기본 감정과 표정이 있다 | 대부분의 표정 인식 데이터셋·서비스가 이 분류를 쓴다. 웹캠 표정 신호의 출발점 어휘로 사용 |
| 감정 바퀴 (Plutchik) | 8개 기본 감정의 강도·조합으로 복합 감정이 생긴다 | '여러 감정이 동시에 존재'를 시각화할 근거 |
| 차원 모델 (Russell 원형 모델) | 감정을 쾌–불쾌(valence), 각성(arousal) 두 축의 연속 공간으로 본다 | 색·움직임 속도 같은 연속적 시각 요소와 잘 맞는다 |
| 구성된 감정 이론 (Barrett) | 감정은 고정된 표정 신호가 아니라 상황·경험·언어로 구성된다. 2019년 리뷰는 표정만으로 감정을 추론하는 근거가 약하다고 정리 | 표정은 '단서'로만 쓰고 판정하지 않는다. 표정 신호(겉)와 사용자가 붙인 이름(속)을 나란히 보여 주는 구조의 근거 |
| 감정 세분화 (emotional granularity) | 감정을 세밀한 단어로 구분하는 사람이 스트레스 대처를 더 잘한다는 연구가 있다 | "감정에 이름 붙이기"를 결과물의 가치로 제시할 근거 |
| 정서 컴퓨팅 (Picard, 1997~) | 컴퓨터가 감정을 인식·표현·반응하는 연구 분야 | 컴퓨터공학 쪽 연구 계보. 표정·음성·텍스트·생체신호·멀티모달 인식으로 확장 |
| 감정 분석 / LLM | 텍스트의 감정·감성 분류, 최근엔 대화형 AI의 공감 응답 연구 | 〈에이전트 루비〉와 연결: AI의 감정 표현이 사용자의 해석을 바꾼다 |
| 윤리·규제 | 감정 인식은 편향·사생활 문제가 지적되며, EU AI Act는 직장·교육 현장의 감정 인식을 금지 | 웹캠은 사용자가 직접 켜는 방식으로만 쓰고, 영상은 브라우저 안에서만 처리하며 저장·전송하지 않는다. 누군가를 평가하는 용도로 쓰지 않는다 |
| 표정 인식 (FER) | 얼굴 표정 이미지를 기본 감정으로 분류하는 연구. 정서 컴퓨팅에서 가장 활발하고 대중에게 익숙한 분야 | 일반 사용자가 "감정 인식"을 가장 직관적으로 체감하는 입력이라 MVP에 포함. 단, 조명·안경·인종·연령에 따른 정확도 편차가 보고돼 있어 결과를 확정값으로 보여 주지 않는다 |

## Evidence
- 관람 관찰 1 (〈701호〉, 대학로 우리소극장, 90분): 같은 사건에도 인물마다 다른 감정(압박 vs 통제 상실 불안)이 생기고, 겉으로 드러난 감정과 속 감정이 다를 수 있다.
- 관람 관찰 2 (〈에이전트 루비〉, 서울시립미술관 서소문본관): AI의 표정 변화만으로 관람자가 감정을 읽어 낸다. 감정 해석에는 보는 사람의 기대가 섞인다.
- 연구 근거: 위 Background의 Barrett 리뷰, 감정 세분화 연구.
- 사용자 반응: **Assumption — 프로토타입 사용자 테스트(4주차)로 검증 필요.** "단정하지 않는 방식이 더 공감된다"는 실제 사용자 데이터는 아직 없다.

## Users
- **Primary**: 자기 감정을 말로 정리하기 어려운 대학생·청년. 과제·시험·관계로 마음이 복잡할 때, 일기 대신 짧게(5분 안팎) 감정을 들여다보고 싶을 때 사용한다.
- **Secondary**: 과제 평가자·수업 동료(결과물 발표 관람자), 감정 관련 UI를 만들려는 개발자(설계 원칙 참고).
- **Not for**: 우울·불안 등 정신건강 진단이나 상담이 필요한 사람. 이 결과물은 진단 도구가 아니며 화면에 그렇게 안내한다.

## 결과물 가치 (피드백 3 반영)
- **무엇을 위해**: 감정을 판정하지 않고, 사용자가 자기 감정을 마주하고 이름 붙이도록 돕는다.
- **왜 만드는가**: 두 관람에서 얻은 두 가지 생각을 직접 확인하려고 만든다. 하나는 "감정은 상황을 알아야 읽을 수 있고 여러 이름이 동시에 붙는다"(701호)이다. 다른 하나는 "기술은 사용자의 일부만 보므로, 사용자가 해석을 직접 고칠 수 있어야 한다"(나의 [나]들)이다.
- **활용처**:
  1. 개인 감정 기록 — 하루 끝 짧은 셀프 체크인
  2. 전시·발표 — 관람자가 직접 참여하는 인터랙티브 작품
  3. 설계 사례 — "AI는 제안, 사람은 결정" 원칙을 감정 UI에 적용한 프로토타입(향후 개인화 서비스 개발의 기준)
- **전달력**: 결과가 글이 아니라 색·형태·움직임으로 된 한 장의 이미지로 남는다. 말로 설명하기 어려운 감정을 남에게 보여 주거나 시간에 따라 비교할 수 있다.

## Hypothesis
We believe **웹캠 표정·카드 질문·마우스 입력을 추상 이미지로 바꾸고, 그 감정 이름을 사용자가 직접 고르고 섞어 고칠 수 있는 웹아트**가
**자기 감정을 한 단어로 단정하지 않고 더 세밀하게 인식하는 경험**을 **대학생 사용자**에게 줄 것이다.
We'll know we're right when **테스트 참여자 다수가 "결과 이미지가 지금 내 감정과 닮았다"고 답하고, 처음 제안된 감정 이름보다 더 많은(또는 다른) 감정 이름을 스스로 붙일 때**.

## Scope
**MVP** — 브라우저에서 바로 실행되는 1페이지 웹아트.
1. 사용자가 원하면 웹캠을 켠다. 표정에서 읽힌 감정 신호가 실시간으로 화면의 색·움직임에 반영된다.
2. 감정 카드 질문 몇 개에 답하고, 마우스 움직임으로 화면에 흔적을 남긴다.
3. 입력이 실시간으로 색·선·형태·움직임의 추상 이미지로 바뀐다.
4. 마지막에 "표정에서는 이런 감정이 보여요" 식으로 여러 감정 후보를 **제안만** 한다.
5. 사용자가 감정 이름을 고르고·섞고·직접 쓰면 이미지가 그에 맞게 바뀐다.
6. 결과 화면에 **표정 신호(겉으로 보인 감정)**와 **사용자가 붙인 이름(스스로 느낀 감정)**을 두 겹으로 함께 보여 준다. 둘이 다르면 그 차이 자체를 작품 요소로 표현한다(〈701호〉의 '화처럼 들리는 두려움').
7. 완성 이미지를 저장할 수 있다.
8. 진단 도구가 아니라는 안내, 카메라 영상은 기기 밖으로 나가지 않고 저장되지 않는다는 안내를 보여 준다.
9. 웹캠을 거부하거나 카메라가 없어도 카드 질문 + 마우스만으로 끝까지 사용할 수 있다.

**Out of scope**
- 카메라 영상·사진의 저장, 서버 전송 — 사생활 보호. 결과는 추상 이미지로만 남긴다.
- 얼굴로 사람을 식별하거나 나이·성별 등을 추정하는 기능 — 감정 탐구와 무관하고 위험만 크다.
- 표정 인식 모델을 직접 학습시키는 일 — 4주 안에 불가능. 이미 공개된 모델을 쓴다.
- 음성·생체신호 입력 — 기간(4주) 대비 과함.
- 계정·로그인·감정 기록 누적 — 개인정보 저장 부담. 기록은 사용자가 이미지를 직접 저장하는 방식으로 대신한다.
- 정신건강 진단·조언·상담 — 책임 범위 밖.
- 모바일 앱 — 웹으로 충분.
